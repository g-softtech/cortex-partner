# Cortex Partner Program — Change Request

**Version:** 1.0  
**Location:** Inside the relevant project  
**Audience:** Approved Partners

## Purpose

A Change Request is used when a Partner needs a change to the project after development has started.

## Information

Collect:

- Project
- Description of requested change
- Page/feature affected
- Reason or context
- Screenshot or supporting file where useful

## Review

Cortex reviews the request and determines whether it is within the agreed project scope.

Possible outcomes:

- IN_SCOPE
- ADDITIONAL_WORK
- CLARIFICATION_REQUIRED
- REJECTED

Where a request is additional work, Cortex may provide revised pricing and/or timeline before work proceeds.

## Principle

The Change Request process protects both the Partner and Cortex by creating a clear record of what was requested and how it was handled.

Do not treat every new customer request as automatically included in the original project.

## Status

The implementation should use the existing production Change Request status model where one already exists.
